# フィーチャー仕様: Ver.2 相当フル UI オプション

**フィーチャーブランチ**: `004-full-ui-options`
**作成日**: 2026-05-03
**ステータス**: 草稿

## ユーザーシナリオとテスト *（必須）*

### ユーザーストーリー 1 - ビジュアライズオプションの設定（優先度: P1）

ユーザーは、キューブ画像の見た目を細かく制御したい。特定のステップ（OLL, F2L など）を
練習しているとき、関係ない面をグレーアウトしたり、上から見た "plan view" に切り替えたり
することで、アルゴリズムの理解が深まる。

**この優先度の理由**: Ver.2 で最も使われているビジュアライズ機能であり、Ver.3 の価値提案の中核。

**独立テスト**: Special View・Stage Mask の UI を操作するだけで、すぐに表示が変わることを確認できる。

**受け入れシナリオ**:

1. **Given** アプリを開いた初期状態、**When** Special View を "plan" に切り替えた、**Then** キューブが真上から見た平面図で表示される
2. **Given** 初期状態、**When** Stage Mask に "OLL" を選んだ、**Then** U 面と LL 以外のステッカーがグレーアウトされる
3. **Given** Stage Mask が "OLL" に設定されている、**When** Mask Alg に "y" を選んだ、**Then** マスクの向きが Y 軸方向に 1 回転した状態で表示される
4. **Given** Stage Mask が設定されている、**When** "なし" を選んだ、**Then** 全面が通常色で表示される

---

### ユーザーストーリー 2 - カラースキームの編集（優先度: P1）

ユーザーは、U/R/F/D/L/B 各面の色を任意に変更したい。配色を変えることで、
自分のキューブや図解の色に合わせた画像を生成できる。

**この優先度の理由**: Ver.2 で日常的に使われる機能であり、カスタマイズの基本。

**独立テスト**: 各面のカラーピッカーを変更すると即座にキューブ表示が更新されることを確認できる。

**受け入れシナリオ**:

1. **Given** デフォルト配色の状態、**When** U 面のカラーピッカーで任意の色を選んだ、**Then** Up 面のステッカーが選んだ色で表示される
2. **Given** 任意の配色、**When** x ボタンを押した、**Then** U/F/D/B の色が X 軸回転相当で1ステップ循環する
3. **Given** 任意の配色、**When** y ボタンを押した、**Then** F/R/B/L の色が Y 軸回転相当で1ステップ循環する
4. **Given** 任意の配色、**When** z ボタンを押した、**Then** U/R/D/L の色が Z 軸回転相当で1ステップ循環する
5. **Given** 変更した配色、**When** Reset ボタンを押した、**Then** WCA 標準色（白/赤/青/黄/橙/緑）に戻る

---

### ユーザーストーリー 3 - ビューポート回転の調整（優先度: P1）

ユーザーは、キューブを見る角度を3軸で細かく調整したい。
デフォルト（Y=45°、X=−34°）以外の視点でキューブを確認・共有できる。

**この優先度の理由**: Ver.2 のコア機能。特定のアルゴリズムを上から・横から見せたいユースケースが多い。

**独立テスト**: 各軸スライダーを動かすとリアルタイムにキューブの視点が変わることを確認できる。

**受け入れシナリオ**:

1. **Given** デフォルトビューポート（Y=45°, X=−34°, Z=0°）、**When** Y スライダーを 90° に動かした、**Then** キューブが Y 軸に 90° 回転した角度で表示される
2. **Given** 任意のビューポート設定、**When** 軸ごとの Reset ボタンを押した、**Then** その軸の角度がデフォルト値に戻る
3. **Given** スライダーで角度を変更した、**When** 数値入力フィールドに −180〜180 の値を直接入力した、**Then** その値がスライダーと同期して反映される

---

### ユーザーストーリー 4 - 外観設定（優先度: P2）

ユーザーは、背景色・キューブの輪郭色・マスク色・不透明度・投影距離を調整したい。
透明背景や特定の背景色で、ドキュメントや動画に合わせた画像を生成できる。

**この優先度の理由**: ビジュアル品質を高める機能だが、なくても基本用途は成立する。

**独立テスト**: 各外観設定を変更すると即座にキューブ表示が反映されることを確認できる。

**受け入れシナリオ**:

1. **Given** 初期状態、**When** 背景色を変更した、**Then** キューブ画像の背景が指定色で表示される
2. **Given** 初期状態、**When** キューブ不透明度スライダーを 50% にした、**Then** キューブの枠線が半透明になる
3. **Given** 初期状態、**When** ステッカー不透明度スライダーを 0% にした、**Then** ステッカーが透明になる
4. **Given** 初期状態、**When** 投影距離（dist）を最大値にした、**Then** キューブが正射影に近い見た目になる

---

### ユーザーストーリー 5 - 画像サイズの変更（優先度: P2）

ユーザーは、生成するキューブ画像のサイズを細かく調整したい。
SNS 投稿用に大きめ、ドキュメント埋め込み用に小さめ、など用途に合わせてサイズを選べる。

**この優先度の理由**: 実用性を高める機能だが、デフォルトサイズでも基本用途は成立する。

**独立テスト**: サイズ変更ボタンを押すとキューブ表示領域が即座に変わることを確認できる。

**受け入れシナリオ**:

1. **Given** デフォルトサイズ（128px）、**When** +10 ボタンを 3 回押した、**Then** サイズが 158px になりキューブが大きく表示される
2. **Given** 任意のサイズ、**When** Reset ボタンを押した、**Then** サイズが 128px に戻る
3. **Given** 最小値（1px）付近、**When** −10 ボタンを押した、**Then** 1px 未満には下がらない（下限クランプ）

---

### ユーザーストーリー 6 - レイアウト改善（優先度: P1）

ユーザーは、キューブ表示と設定パネルを同時に見ながら操作したい。
設定を変えるたびにスクロールしてキューブを確認するのは非効率。

**この優先度の理由**: 操作の流れを根本的に改善するレイアウト変更。他の機能の使いやすさに直結する。

**独立テスト**: 設定パネルをスクロールしても左のキューブ表示が常に見える位置に固定されていることを確認できる。

**受け入れシナリオ**:

1. **Given** アプリを開いた状態、**When** 右側の設定パネルをスクロールした、**Then** 左側のキューブ表示は画面内に固定されたまま（sticky）
2. **Given** 任意の設定パネル操作、**When** 設定を変更した、**Then** 左側のキューブがリアルタイムで更新される

---

### エッジケース

- 画像サイズが 1 未満の値を指定しようとした場合、1px にクランプされる
- Stage Mask を設定した状態でキューブサイズを変更した場合、マスクは引き続き有効に機能する
- 無効なカラーコードがカラーピッカー以外から入力された場合、表示は崩れずデフォルト値にフォールバックする
- ビューポート回転の角度に −180〜180 の範囲外の値が入力された場合、範囲内にクランプされる

## 要件 *（必須）*

### 機能要件

- **FR-001**: システムは Special View（normal / plan）をラジオボタンで切り替えられなければならない（MUST）
- **FR-002**: システムは 20 種類の Stage Mask をドロップダウンで選択できなければならない（MUST）
- **FR-003**: Stage Mask 選択中は Mask Alg（x/x'/x2/y/y'/y2/z/z'/z2）をドロップダウンで選択できなければならない（MUST）
- **FR-004**: ユーザーは U/R/F/D/L/B 各面の色をカラーピッカーで変更できなければならない（MUST）
- **FR-005**: カラースキームは x/y/z 軸回転ボタン（各1ステップ循環）と Reset ボタンを提供しなければならない（MUST）
- **FR-006**: ビューポート回転は 3 スロット各々で軸（x/y/z）+ 角度（−180〜180°）を設定できなければならない（MUST）
- **FR-007**: ビューポート回転の各スロットにはスライダーと数値入力フィールドが同期して動作しなければならない（MUST）
- **FR-008**: 外観設定として背景色・キューブ色・マスク色のカラーピッカーを提供しなければならない（MUST）
- **FR-009**: キューブ不透明度とステッカー不透明度を 0〜100% のスライダーで調整できなければならない（MUST）
- **FR-010**: 投影距離（dist）を 1〜100 のスライダーで調整できなければならない（MUST）
- **FR-011**: 画像サイズを −10/−1/+1/+10 ボタンとスライダーと Reset ボタンで制御できなければならない（MUST）
- **FR-012**: パズルサイズ選択に ＋/− ボタンを追加しつつ、既存の select 要素も維持しなければならない（MUST）
- **FR-013**: 左列にキューブ表示・右列に設定パネルの二列レイアウトで、左列は sticky に固定されなければならない（MUST）
- **FR-014**: 全設定変更はキューブ表示にリアルタイムで反映されなければならない（MUST）
- **FR-015**: `RenderOptions` 型に view/mask/maskAlg/cubeColor/maskColor/cubeOpacity/stickerOpacity/dist/arrows フィールドを追加しなければならない（MUST）
- **FR-016**: `SrVisualizerAdapter` は拡張された全オプションを sr-visualizer に渡さなければならない（MUST）
- **FR-017**: `useRenderOptionsStore`（Pinia）が全ビジュアライズ設定を管理しなければならない（MUST）
- **FR-018**: 既存テスト（vitest）が全て引き続き通過しなければならない（MUST）

### 主要エンティティ

- **RenderOptions**: ビジュアライズオプション全体を表す型。既存フィールドを維持しつつ新規フィールドを追加。
- **useRenderOptionsStore**: 全ビジュアライズ設定の状態を保持する Pinia ストア。
- **SrVisualizerAdapter**: RenderOptions を sr-visualizer ライブラリの ICubeOptions に変換するアダプタ。

## 成功基準 *（必須）*

### 測定可能なアウトカム

- **SC-001**: ユーザーは5秒以内に Special View・Stage Mask・カラースキーム・ビューポート・外観の全設定にアクセスできる（スクロールのみで到達可能）
- **SC-002**: 全設定変更はユーザー操作から 100ms 以内にキューブ表示に反映される（知覚的なリアルタイム性）
- **SC-003**: Ver.2 が持つビジュアライズオプション（Special View, Stage Mask 20種, カラースキーム, ビューポート3軸, 外観設定6項目, 画像サイズ）が全て操作可能である
- **SC-004**: 既存の vitest テストが全件パスする（テスト件数の減少なし）
- **SC-005**: TypeScript 型チェック（`vue-tsc --noEmit`）がエラーなしで通過する

## 前提条件

- ユーザーはモダンブラウザ（Chrome/Firefox/Safari の最新版）を使用している
- Ver.2 と同様に Bootstrap 5 を CDN 経由で導入してレイアウトに利用する
- sr-visualizer ライブラリ（v1.0.13）が提供する全オプション（mask, view, cubeColor 等）をそのまま利用する
- 既存の `useCubeStore` および `useCubePersist` は変更しない
- アロー定義 UI は Ver.2 の完全な GUI ではなく、テキスト入力（arrows 文字列）のみとする（簡略化）
- 画像サイズは幅・高さ共通の正方形サイズとして扱う
- スタイリングは Bootstrap 5 CSS クラスを主体とし、最小限のカスタム CSS を追加する
