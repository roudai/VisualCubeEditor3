# フィーチャー仕様: 拡張記法対応（M / E / S / u / r / f / d / l / b / x / y / z）

**フィーチャーブランチ**: `005-extended-notation`
**作成日**: 2026-05-06
**ステータス**: 草稿

## 背景

現在の手順パーサーは WCA 標準の外層ムーブ（U / D / F / B / R / L）と
数字プレフィックス（2R / 3U）・w サフィックス（Uw / Rw）しか受け付けない。
しかし内部的に `Uw` を適用すると 3×3 では `maxSlice` の制約に引っかかりエラーになる
（実質 wide ムーブは 3×3 で動作しない）。

Ver.2 では以下の記法がすべて動作しており、Ver.3 での再現が必要：

| カテゴリ | 記法 |
|---------|------|
| 中層ムーブ | M E S（+ 修飾子 `'`, `2`） |
| ワイドムーブ（小文字） | u d r l f b（+ 修飾子 `'`, `2`） |
| ワイドムーブ（w サフィックス） | Uw Dw Rw Lw Fw Bw（既存・動作修正が必要） |
| キューブ回転 | x y z（+ 修飾子 `'`, `2`） |
| 数字プレフィックス | 2R 3U 等（既存・継続） |

---

## ユーザーシナリオとテスト

### ユーザーストーリー 1 — 中層ムーブの入力（優先度: P1）

キューブを練習するユーザーは、M / E / S 記法で内層だけを動かしたい。
例えば M2 スクランブル（`M U M' U'`）を手順テキストボックスに入力するだけで
キューブへリアルタイム反映させられる。

**受け入れシナリオ**:

1. **Given** 初期状態（完成形）、**When** テキストボックスに `M` と入力した、
   **Then** キューブが M ムーブ（中央列を L 方向に回転）を反映した状態で表示される
2. **Given** 初期状態、**When** `M2` と入力した、
   **Then** M を 2 回適用した状態になる
3. **Given** 初期状態、**When** `M U M' U'` と入力した、
   **Then** 4 手の連続手順が正しく適用される
4. **Given** 初期状態、**When** `E` と入力した、
   **Then** E ムーブ（赤道層を D 方向に回転）が反映される
5. **Given** 初期状態、**When** `S` と入力した、
   **Then** S ムーブ（垂直中央層を F 方向に回転）が反映される

---

### ユーザーストーリー 2 — ワイドムーブの入力（優先度: P1）

3×3 以上のキューブを使うユーザーは、u / r / Uw / Rw 等のワイドムーブを
テキストボックスに入力して複数層をまとめて動かしたい。

**受け入れシナリオ**:

1. **Given** 初期状態、**When** `u` と入力した、
   **Then** U 面と E' 層（U 方向に揃えた赤道隣接層）が同時に回転した状態になる
2. **Given** 初期状態、**When** `Uw` と入力した、
   **Then** `u` と同じ結果になる
3. **Given** 初期状態、**When** `r` と入力した、
   **Then** R 面と M' 層が同時に回転した状態になる

---

### ユーザーストーリー 3 — キューブ回転の入力（優先度: P1）

アルゴリズムの手順にキューブ回転（x / y / z）が含まれるユーザーは、
テキストボックスにそのまま入力して全層を回転させたい。

**受け入れシナリオ**:

1. **Given** 初期状態、**When** `x` と入力した、
   **Then** キューブ全体が R 軸回りに 90° 回転した状態になる（U→F→D→B サイクル）
2. **Given** 初期状態、**When** `y` と入力した、
   **Then** キューブ全体が U 軸回りに 90° 回転した状態になる（F→R→B→L サイクル）
3. **Given** 初期状態、**When** `z` と入力した、
   **Then** キューブ全体が F 軸回りに 90° 回転した状態になる（U→R→D→L サイクル）
4. **Given** 初期状態、**When** `x'` と入力した、
   **Then** x の逆回転が適用される
5. **Given** 5×5 キューブ選択中、**When** `y` と入力した、
   **Then** 5×5 全 5 層が正しく回転する

---

### ユーザーストーリー 4 — 面ボタンから新記法を入力（優先度: P2）

ユーザーはテキスト入力なしに、面ボタンをクリックするだけで
M / E / S / x / y / z を手順テキストボックスへ追記したい。

**受け入れシナリオ**:

1. **Given** テキストボックスが空、**When** M ボタンをクリックした、
   **Then** テキストボックスに `"M"` が追記される（ボタン実装は段階的に追加）
2. **Given** テキストボックスに `"R U"` がある、**When** x ボタンをクリックした、
   **Then** テキストボックスが `"R U x"` になる

---

### エッジケース

- `M'` / `M2` / `E'` / `E2` / `S'` / `S2` / `x'` / `x2` / `y'` / `y2` / `z'` / `z2` がすべて正しく解析される
- `m`（小文字 M）は不正記法としてエラーになる（WCA では使用しない）
- 2×2 キューブ選択中に `M` を入力した場合、内層が存在しないためエラーになる
- 4×4 以上で `x` を入力したとき、全層がサイズに応じて正しく展開される

---

## 要件

### 機能要件

- **FR-001**: パーサーは M / E / S を中層ムーブとして解析できなければならない（MUST）
- **FR-002**: パーサーは u / d / r / l / f / b を対応する外層＋内層の 2 ムーブに展開できなければならない（MUST）
- **FR-003**: 既存の Uw / Dw / Rw / Lw / Fw / Bw も FR-002 と同様に 2 ムーブに展開しなければならない（MUST）
- **FR-004**: パーサーは x / y / z をキューブサイズに応じた全層ムーブの連続に展開できなければならない（MUST）
- **FR-005**: M / E / S / x / y / z すべてに `'`（CCW）と `2`（Double）修飾子が使えなければならない（MUST）
- **FR-006**: `applyMove` は 3×3 で sliceIndex=1（中層）を受け付けなければならない（MUST）
- **FR-007**: 面ボタンに M / M' / E / E' / S / S' / x / x' / y / y' / z / z' を追加しなければならない（MUST）
- **FR-008**: `parseNotation` は `size: CubeSize` パラメータを受け取り、x / y / z の展開に使用しなければならない（MUST）
- **FR-009**: MoveInput はパーサーにキューブの現在サイズを渡さなければならない（MUST）
- **FR-010**: 既存テストが全件パスしなければならない（MUST）

### 主要エンティティ（変更対象）

- **`notation.ts`**: `parseNotation` シグネチャ拡張・新トークン追加・ワイドムーブ展開ロジック追加
- **`rotation.ts`**: `maxSlice` 計算の修正（`Math.floor` → `Math.ceil`）
- **`MoveInput.vue`**: `store.size` をパーサーに渡す・新規面ボタン追加

## 成功基準

- **SC-001**: M / E / S / u / r / f / d / l / b / Uw / Rw / x / y / z がテキスト入力でキューブに反映される
- **SC-002**: 3×3 で `Uw`（= `u`）が正しく 2 層ムーブとして動作する（現在は動作しない）
- **SC-003**: x / y / z が 2×2〜7×7 全サイズで正しく全層を回転させる
- **SC-004**: `vue-tsc --noEmit` がエラーなしで通過する
- **SC-005**: 全 Vitest テストがパスする（テスト件数が増加する）
